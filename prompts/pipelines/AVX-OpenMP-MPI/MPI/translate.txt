## MPI structure

### Initialization and finalization
- Call `MPI_Init(&argc, &argv)` at the start and `MPI_Finalize()` at the end.
- Obtain `MPI_Comm_rank(MPI_COMM_WORLD, &rank)` and `MPI_Comm_size(MPI_COMM_WORLD, &size)`.

### Domain decomposition
- Decompose the primary parallel dimension (usually the outermost loop) across MPI ranks.
- Each rank computes its local chunk: `local_start = rank * (N / size)`, handle remainder with the last rank.
- Allocate only the local portion of large arrays on each rank. Adjust SIMD loops to operate on the local chunk.

### Communication
- Use collective operations when possible: `MPI_Reduce`, `MPI_Allreduce`, `MPI_Gather`, `MPI_Scatter`, `MPI_Bcast`.
- Prefer non-blocking communication for halo exchanges when computation can overlap.

### Output
- Only rank 0 collects the global result and prints the checksum/output.
- Use `MPI_Gather` or `MPI_Reduce` to assemble the global result on rank 0.

### Timing
- Use `MPI_Wtime()` for timing and call `MPI_Barrier(MPI_COMM_WORLD)` immediately before recording the start time.
- Every rank computes its own `double elapsed_ms`.
- Declare `double max_elapsed_ms = 0.0;` and make all ranks, outside any `if (rank == 0)` block and outside OpenMP parallel regions, call:
  `MPI_Reduce(&elapsed_ms, &max_elapsed_ms, 1, MPI_DOUBLE, MPI_MAX, 0, MPI_COMM_WORLD);`
- Only rank 0 prints the timing, using `max_elapsed_ms` rather than its local `elapsed_ms`.

## OpenMP within MPI
- Keep `#pragma omp parallel for` on loops that were already parallelized, but now operating on the LOCAL MPI chunk.
- Adjust loop bounds to local indices: `for (int i = local_start; i < local_end; i++)`.
- Keep OpenMP clauses (`default(none)`, `shared`, `private`, `reduction`).

## AVX within OpenMP within MPI
- If the timed kernel is SIMD, the inner loop operates on each thread's sub-chunk of the MPI-local data.
- Ensure that each thread's data slice is naturally aligned, or switch from aligned to unaligned loads (`_mm512_loadu_pd`, `_mm256_loadu_pd`) if alignment is uncertain after chunking.
- Existing three-branch SIMD must remain intact. Vetoed kernels stay scalar.

## What NOT to do
- Do NOT remove existing SIMD branches.
- Do NOT invent SIMD for a vetoed kernel (`// SIMD skipped:`).
- Do NOT remove `#pragma omp` directives — adjust their loop bounds.
- Do NOT remove AVX intrinsic code or alignment attributes when present.
- Do NOT add MPI calls inside OpenMP parallel regions.
- Do NOT change the algorithm.
