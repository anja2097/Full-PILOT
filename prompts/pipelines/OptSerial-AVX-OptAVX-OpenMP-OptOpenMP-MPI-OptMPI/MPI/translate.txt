## MPI structure

### Initialization and finalization
- Call `MPI_Init(&argc, &argv)` at the start and `MPI_Finalize()` at the end.
- Obtain `MPI_Comm_rank(MPI_COMM_WORLD, &rank)` and `MPI_Comm_size(MPI_COMM_WORLD, &size)`.

### Domain decomposition
- Decompose the primary parallel dimension (the outermost loop) across MPI ranks.
- Each rank computes a contiguous local chunk. Handle the remainder so the last rank covers through `N` and no element is skipped or double-counted.
- Allocate only the local portion of large arrays on each rank. The `#pragma omp parallel for` iterates that local range; the SIMD (or scalar) inner loop stays inside the thread.
- Each element of the original timed loop is computed by exactly one rank. Replicating that full loop on every rank, then printing from rank 0, is not a distribution: the same work runs `size` times.
- A global scalar (checksum, sum, norm, max) is the `MPI_Reduce` / `MPI_Allreduce` of each rank's contribution over its own chunk. Rank 0 does not obtain it by executing the full kernel locally.
- Do NOT gather the full domain to rank 0, compute there, and scatter the result. That serializes the kernel.

### Communication
- Prefer collectives (`MPI_Reduce`, `MPI_Allreduce`, `MPI_Bcast`, `MPI_Scatter`, `MPI_Gather`) over manual `MPI_Send`/`MPI_Recv` loops when the pattern matches.
- **`MPI_Alltoall` / `MPI_Alltoallv` only** when the result layout across ranks differs from the input layout (a global transposition, an FFT butterfly) and each pair of ranks exchanges a block. A scalar or a partial reduction is `MPI_Reduce` / `MPI_Allreduce` / `MPI_Reduce_scatter`, not `MPI_Alltoall`.
- Halo exchanges stay outside OpenMP regions. Non-blocking `MPI_Isend`/`MPI_Irecv` are allowed when interior work can run before `MPI_Waitall`.

### Independent element maps
When each output element depends only on its own index (no neighbour reads), do not build the full arrays on rank 0 and scatter them (this refers to the computed arrays; pseudo-random input generation follows the section "Input data generated with a pseudo-random generator"). Each rank generates its own contiguous slice:
- Any buffer rank 0 still allocates for I/O or the checksum uses `posix_memalign` at 64 bytes, not `malloc` and not `std::vector`.

### Timing
- Replace `omp_get_wtime()` / `std::chrono` / `clock_gettime` with `MPI_Wtime()`.
- All ranks call `MPI_Barrier(MPI_COMM_WORLD)` **immediately before** the start `MPI_Wtime()`.
- Do NOT call `MPI_Barrier` between the start `MPI_Wtime` and the stop `MPI_Wtime`. Communication the kernel needs stays outside that window.
- Every rank computes `double elapsed_ms`. Then **all ranks**, outside any `if (rank == 0)` and outside every OpenMP region, call:
  `MPI_Reduce(&elapsed_ms, &max_elapsed_ms, 1, MPI_DOUBLE, MPI_MAX, 0, MPI_COMM_WORLD);`
- Declare `double max_elapsed_ms = 0.0;`. Only rank 0 prints `max_elapsed_ms`.

## OpenMP and SIMD inside the rank
- Keep `#pragma omp parallel for` on loops that were already parallel, now over the LOCAL chunk (`local_start` .. `local_end`).
- Keep `default(none)` and the existing clauses. Add `rank`, `local_start`, and `local_end` as `shared` or `firstprivate` if the region uses them.
- If the timed kernel is SIMD, the inner loop runs on each thread's sub-chunk of the MPI-local data. If `local_start` is not 64-byte aligned, use `_mm512_loadu_pd` / `_mm256_loadu_pd`.
- The tail of a local chunk uses the local length, not the global `N`.

## Input data generated with a pseudo-random generator
If the program fills its input data with a pseudo-random generator (rand, random, drand48, rand_r, std::mt19937 / std:: distributions, or a hand-written generator), that generation code must produce exactly the same values, in the same order, as in the input program:
- Do NOT put it inside an OpenMP parallel region and do NOT split it across threads.
- Do NOT split it across MPI ranks, skip generator calls, reseed, or reorder which array is generated first.
- With MPI, every rank runs the original generation code unchanged (full arrays, same order) and then uses its own slice; this happens outside the timed region, so it does not affect the measured time. If the arrays are too large to replicate, rank 0 runs the original generation code and distributes the slices with MPI_Scatterv / MPI_Bcast, also outside the timed region.
- This applies only to data generation. The timed kernel is what you parallelize.
- If the generator is called INSIDE the timed kernel, keep its sequence of calls serial and identical to the input program.
